    The Knowledge Base — A Field Guide

    The S-BOS Knowledge Base is where Stitser BUILT's processes, roles, training, and reference material live — organized for action. This article is your map for using it.

    ⏱ 8 min read Last updated: June 2026 Pillar: Systems

    Structure and Navigation

    The Knowledge Base is organized into six top-level sections, each accessible from the navigation bar at the top of every page. Think of them as the six rooms in a house — each room has a clear purpose and everything in it belongs there.

    System How S-BOS works — architecture, Kompass, the platform overview, and foundational orientation articles like this one.
    Workflows Step-by-step value chain process maps for every product line — who does what at each stage, and how S-BOS supports it.
    Agents Reference guides for every Kompass skill — what it does, when to invoke it, and what to expect.
    Roles Role-specific guides for every position at Stitser BUILT — Practitioner, Production Manager, Ops Manager, Broker.
    What's New Recent system updates, new workflow documents, and changes to protocols — the running changelog for S-BOS.
    Glossary Definitions for S-BOS terms, acronyms, and vocabulary used across the system and in Kompass conversations.

    How to use it

    The Knowledge Base is designed to be browsed by section and searched by need. A few patterns that work well:

    • Starting a new task? Go to Workflows → find the process for your situation → follow the value chain.
    • Unsure about your role's responsibilities? Go to Roles → your role page lists your obligations at every stage.
    • Asking Kompass something and not sure what skill to use? Go to Agents → skim the skill names and descriptions.
    • Learning the system for the first time? Start with the System section → begin with "Welcome to S-BOS" → work through the System Introduction course.
    Kompass shortcut

    You can ask Kompass "where do I find X in the Knowledge Base?" and it will point you to the right page. The Knowledge Base and Kompass are designed to work together — Kompass knows every article, workflow, and role guide here.

    Article Types

    Not every piece of content looks the same. The Knowledge Base uses three HTML templates, each designed for a different kind of information. Knowing the template type tells you immediately how to interact with the content.

    Article
    Long-form reference content with a sticky sidebar table of contents. Sections, callout boxes, tables, and blockquotes.
    Used for: orientation, concepts, how-to explanations, role guides, system documentation.
    Workflow
    Step-by-step process map with a clickable stage selector. Each stage shows Who, What, Tool, and Output in side-by-side panels.
    Used for: value chain processes, escrow stages, deal workflows, handoff protocols.
    Slide Deck
    Full-screen slides with keyboard navigation, a progress bar, and a "Mark Complete" button on the final slide.
    Used for: onboarding, training modules, orientation sessions, sequential learning.

    All three template types share the same lesson meta bar at the top — showing the learning track, course, pillar, content type, estimated time, and a Mark Complete button that logs your progress to S-BOS.

    How Content Is Organized

    Content in the Knowledge Base is organized two ways simultaneously. Every piece of content belongs to both a navigation section (where you find it by browsing) and a learning hierarchy (where it appears in a training course).

    Learning Tracks and Courses

    Training content is organized into a three-level hierarchy that mirrors how learning actually works — broad → focused → specific.

    Track
    The broad subject area. Example: "S-BOS Foundations" — covers everything a new team member needs to understand about the operating system.
    Course
    A focused module within a track. Example: "System Introduction" — a sequence of articles that orient a new hire to S-BOS before they start using it day-to-day.
    Lesson
    A single article, workflow, or slide deck. Example: "Welcome to S-BOS" — one article with an estimated read time, a pillar tag, and a Mark Complete button. This article is a lesson.

    The lesson meta bar at the top of every page shows exactly where you are in this hierarchy. The breadcrumb reads: Track › Course › Lesson.

    One file, multiple surfaces

    The same HTML file serves as both a standalone article (findable by browsing) and a lesson in a course (visible in a learning track). There's no separate "training version" of the content — it's the same page in both contexts.

    Workflows

    Workflow pages live in the Workflows section and map the full value chain for a process — every role, every stage, every handoff. They use the Workflow template with a clickable stage bar across the top.

    A workflow page answers three questions for every stage:

    • Who is responsible — Practitioner, Production Mgr, Ops Mgr, Broker, or S-BOS/Claude
    • What needs to happen — the specific action or deliverable at this stage
    • How it gets done — the tool, system, or conversation that makes it happen

    Workflow pages also include a Parallel Value Chains section for situations that can arise at any stage (failed contracts, addenda, timeline changes) and a Team Expectations block that applies across the whole process.

    If you're in the middle of a deal and unsure what to do next — there is a workflow for it. Go to the Workflows section, find your process, click the stage you're in, and follow it.

    Editing Articles and Tracking Changes

    Every page in the Knowledge Base is editable by any team member — no login, no admin access, no request process. The edit workflow is built directly into each page.

    How to edit a page

    1

    Click "✏ Edit page"

    The button is fixed in the bottom-right corner of every page. Click it to enter edit mode.

    2

    Click any highlighted text

    Once in edit mode, every editable text block gets an amber dashed outline and a yellow tint. Click any one to place your cursor and start typing — paragraphs, headings, list items, callout text, and table cells are all editable.

    3

    Click "💾 Save changes"

    When you're done, click the green Save button. A dialog will ask for your name — this is what appears in the edit history. Enter it and confirm.

    4

    Changes go live in ~30 seconds

    Your edit is committed directly to GitHub. GitHub Pages deploys the change automatically. Reload after 30 seconds to see it live.

    What editing doesn't change

    The edit mode lets you change text content — words, sentences, paragraphs, list items. It does not add or remove sections, callout boxes, tables, or structural elements. For layout changes, contact the S-BOS admin to update the source file.

    Viewing edit history

    Every page has a complete edit history accessible at the bottom. Scroll to the footer of any page and click "🕐 Edit history" to expand a panel showing every edit that's been saved — who made it and when.

    The history is backed by GitHub commits, which means it's permanent, ordered, and tamper-proof. Every save is recorded with the editor's name and the exact date and time.

    Try it on this page

    Scroll to the bottom of this article and click "🕐 Edit history" to see the change log for this page. You'll see who last updated it and when.
